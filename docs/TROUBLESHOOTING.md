# Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `KIT_MACHINE_ID is not set` | activation not done, or `.env` not in the directory you run from | run `scripts/setup.sh`, or copy `machine_id` from `peaqos activate --json` into `.env`. `armkit` reads `.env` from the current directory. |
| `armkit check` says `chain: unreachable` | wrong `PEAQOS_RPC_URL`, venue network blocking HTTPS, or the endpoint rate-limited your IP | use the hackathon endpoint mentors handed out, not a public one. If the whole room is on one IP, public RPCs will block everyone for 30 to 60 min. |
| `activate` exits 2 with `INSUFFICIENT_PEAQ`, even with `--dry-run` | the CLI checks the wallet balance before showing a preview | get the wallet funded first (1.5 PEAQ), then re-run `scripts/setup.sh`: it resumes at activation and keeps your key. |
| `activate` starts asking for a 2FA code | wallet below ~0.5 PEAQ and `--skip-funding` not set, so the Gas Station faucet flow kicked in | Ctrl-C, get funded by a mentor, re-run with `--skip-funding`. |
| `submit_event` fails `NotOwnerOrController` | the signer in `.env` is not the wallet that activated the machine | use the same wallet; `peaqos whoami` shows which one is active. |
| `RateLimitExceeded` from the SDK | too many events for one machine in the SDK's sliding window | the submitter backs off and retries; if it keeps failing, your segmentation is too fine: raise `KIT_MIN_SEGMENT_SECONDS` or `KIT_SETTLE_SECONDS`. |
| events submit but `armkit status` shows 0 | `EVENT_REGISTRY_ADDRESS` points at the 1.0 registry (`0x43c6…`) | mainnet 2.0 registry is `0xA1e7F1d7B24dAb55Dc92491e6d9B89F6E925Ad1e`; `peaqos init` writes it, but check. |
| `armkit verify` says `not on chain` for segments with `status: dry-run` | they were recorded without `--live` | they fail verification, with or without `--include-pending`. Move dev runs to their own folder (`KIT_LOG_DIR=./dev-log`) and record the hand-in with `--live`. `armkit resubmit --include-dry-run` would anchor them, at ~0.04 PEAQ each. |
| `verify` says `hash BAD` | the raw segment file was modified after it was logged | that is the point. Don't edit `motion-log/`. |
| `verify` lists `on-chain motion events for this machine with no segment in this log` | the chain has `joint_motion` events for this machine that the log does not | you handed in an incomplete log, or two people recorded against one machine ID. |
| `rclpy / sensor_msgs not importable` | kit venv can't see the ROS Python packages, or it runs Python 3.12 instead of ROS Humble's 3.10 | `deactivate`, source ROS, then `/usr/bin/python3 -m venv --system-site-packages .venv-ros` (see `docs/ARM.md`). On a Mac, use the Docker container. |
| no segments appear while the arm moves | threshold too high, or velocities reported in different units | `ros2 topic echo` the topic and look at magnitudes; lower `KIT_VELOCITY_THRESHOLD`. |
| the MCR score hasn't changed | by design: Provisioned until 5 activity events or 3 revenue days over ≥ 30 days | nothing to fix; say so in your demo. |
| `batch_submit_events` complains about `currency` | the batch path needs `currency=""` explicitly on activity events; single-event calls default it | the kit uses single-event calls. If you batch, pass `currency=""`. |
| `from_env()` can't find variables although `.env` exists | the SDK does not load `.env` itself | `from dotenv import load_dotenv; load_dotenv()` first (the kit does this in `KitSettings.load`). |
| `activate` says `Missing required env var: IDENTITY_REGISTRY_ADDRESS` (or STAKING / MACHINE_NFT) | `peaqos init` fetches those addresses from GitHub; if the fetch fails it writes them empty and still exits 0 | `scripts/setup.sh` now fills pinned mainnet values after `init`. By hand: `IDENTITY_REGISTRY_ADDRESS=0xb53Af985765031936311273599389b5B68aC9956`, `IDENTITY_STAKING_ADDRESS=0x11c05A650704136786253e8685f56879A202b1C7`, `MACHINE_NFT_ADDRESS=0x2943F80e9DdB11B9Dd275499C661Df78F5F691F9`. |
| `segment N NOT anchored: FutureTimestamp()` | the event timestamp was ahead of the block it landed in (laptop clock a few seconds fast) | fixed: the kit stamps events with chain time. Run `armkit resubmit` to anchor the failed segments from the log; nothing is re-recorded. |
| `segment N NOT anchored: NotAuthorizedSubmitter()` | the signer in `.env` is not the machine's owner or controller | use the wallet that activated the machine; `.venv/bin/peaqos whoami` shows which one is active. |
| `peaqos` says `No module named 'peaq_os_cli'` | a stale `peaqos` from an old global install is shadowing the venv's | `rehash` (zsh) or call `.venv/bin/peaqos` directly. |
| `pip install -e .` fails with a setuptools error, or `python3 --version` says 3.9 | macOS system Python is 3.9; the kit and SDK need 3.10+ | `brew install python@3.12` then `python3.12 -m venv .venv`, or `uv venv --seed -p 3.12 .venv`; then `source .venv/bin/activate`. |
| `peaqos init` fails with `CERTIFICATE_VERIFY_FAILED` | python.org Python 3.13 on macOS ships without root certificates | run `/Applications/Python 3.13/Install Certificates.command`, or use a Homebrew/uv Python. `setup.sh` fills the addresses anyway. |
| `armkit record --live` says `receipt lost … run armkit resubmit` | the transaction was broadcast but the RPC timed out before the receipt came back | nothing is lost. `armkit resubmit` checks the chain for the hash first and only sends if it is really missing. If a transaction from your wallet is still pending, it stops and asks you to run it again in a minute. |
| `verify` fails a segment with `doc BAD` | the raw document is malformed for this machine (wrong `machine_id`, sample row width, non-finite value, time going backwards) | you are verifying the wrong `motion-log/`, or quick-start segments (machine_id 1) ended up in your team log. Keep the quick start in its own `KIT_LOG_DIR`. |
| no segments from the Doosan emulator | fixed in this version: the emulator publishes an all-zero `velocity` array while moving and older kits trusted it | update the kit. The segmenter now ignores zero velocity vectors and differentiates positions. |
| other teams' `/dsr01/joint_states` show up on your laptop | everyone on one Wi-Fi with `ROS_DOMAIN_ID=0` shares the DDS network | `export ROS_DOMAIN_ID=<your team number>` in every shell, or `export ROS_LOCALHOST_ONLY=1`. |
| RViz crashes with `Couldn't open X display` | the doosan launch starts RViz; headless or in a container there is no display | harmless. The driver and the topic keep running. |
| Windows | `setup.sh` is bash | use WSL2 Ubuntu 22.04 for the kit and the emulator. Clone the kit inside the WSL filesystem (`~/`), not under `/mnt/c`. |
